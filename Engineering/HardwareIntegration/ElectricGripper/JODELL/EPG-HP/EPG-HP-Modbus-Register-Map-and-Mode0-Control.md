# EPG-HP Modbus 寄存器映射与 MODE0 控制流程

## 所属领域

```text
Engineering
└─ Hardware Integration
   └─ Electric Gripper
      └─ JODELL
         └─ EPG-HP
```

本文依据《EPG-HP 系列模块化电动夹爪通用详细说明书 V1.1》整理，重点说明参数控制模式 MODE0 的核心控制寄存器、反馈寄存器和基本动作流程。具体型号、固件版本和现场行为仍需通过真机验证。

## 两个核心寄存器区域

```text
控制区：0x03E8 起，主站写入命令和参数
反馈区：0x07D0 起，主站读取状态和结果
```

一个 Modbus 寄存器为 16 bit，但说明书在同一个寄存器的高、低字节中安排了不同字段。因此解析时不能把每个寄存器简单当成一个独立数值。

## MODE0 控制区

参数控制模式下，核心三个寄存器为：

```text
0x03E8：[高字节：MODE1 指令][低字节：控制位]
0x03E9：[高字节：目标位置][低字节：保留/未用于 MODE0 参数]
0x03EA：[高字节：目标力][低字节：目标速度]
```

### 先把三个寄存器看成六个格子

```text
寄存器地址      高字节        低字节
0x03E8        [03E8-H]      [03E8-L]
0x03E9        [03E9-H]      [03E9-L]
0x03EA        [03EA-H]      [03EA-L]
```

使用 FC16 从 `0x03E8` 开始写 3 个寄存器时，报文中的 6 个数据字节会按地址依次填入：

```text
报文数据： 00 09 | FF 00 | FF FF
           └03E8┘ └03E9┘ └03EA┘
```

对应关系为：

| 地址 | 寄存器值 | 高字节 | 低字节 | MODE0 含义 |
| --- | --- | --- | --- | --- |
| `0x03E8` | `0x0009` | `0x00` | `0x09` | 高字节忽略；低字节为控制位 |
| `0x03E9` | `0xFF00` | `0xFF` | `0x00` | 位置为完全闭合；低字节暂不使用 |
| `0x03EA` | `0xFFFF` | `0xFF` | `0xFF` | 力最大；速度最高 |

这里存在三个层次：

```text
第一层：地址决定这是哪个寄存器
第二层：一个寄存器拆成高字节和低字节
第三层：控制字节 0x09 继续拆成单独 bit
```

因此，`0x0009` 既可以被当作一个 16 位寄存器值，也可以进一步解释为高字节 `0x00` 和低字节 `0x09`；低字节 `0x09` 又可以继续解释为多个控制开关。

### 0x03E8 低字节控制位

| bit | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `rACT` | 0 停止/复位，1 使能夹爪 |
| 1 | `rMODE` | 0 参数控制 MODE0，1 无输入参数控制 MODE1 |
| 2 | Reserved | 保留 |
| 3 | `rGTO` | 0 停止，1 按参数运动到目标位置 |
| 4 | `rATR` | 自动巡检/紧急自动释放命令 |
| 5 | `rARD` | 自动巡检/释放方向 |
| 6-7 | Reserved | 保留 |

正常开合动作主要使用 `rACT`、`rMODE` 和 `rGTO`。`rATR` 属于机械臂或设备发生紧急事故后的检查/释放功能，说明书明确提示一般情况下不要执行。

例如 MODE0 下：

```text
rACT = 1
rMODE = 0
rGTO = 1
```

低字节对应：

```text
bit3 bit2 bit1 bit0
  1    0    0    1
= 0b0000_1001
= 0x09
```

因此说明书动作示例将 `0x03E8` 写为 `0x0009`。

### 0x03E9 高字节目标位置

```text
0x00：完全打开
0xFF：完全闭合
中间值：在开合行程之间线性变化
```

例如目标位置为完全闭合时，整个 16 位寄存器示例写为：

```text
0xFF00
  ├─ 高字节 0xFF：目标位置
  └─ 低字节 0x00：未用于该 MODE0 位置参数
```

说明书提醒：夹取物体时，目标位置不应只设置到刚好接触物体的位置，还要保留一定闭合余量，才能让夹爪可靠判断夹持状态。具体换算和余量需要结合型号行程、物体尺寸和真机标定。

### 0x03EA 高低字节

```text
0x03EA 高字节：目标力，0x00 最小，0xFF 最大
0x03EA 低字节：目标速度，0x00 最低，0xFF 最高
```

例如：

```text
0x3CC8
  ├─ 高字节 0x3C：目标力
  └─ 低字节 0xC8：目标速度
```

只写位置、速度或力参数不会自动开始动作，还需要通过 `rGTO` 发出运动命令。

## MODE0 反馈区

核心反馈寄存器为：

```text
0x07D0：[高字节：保留/未列为核心反馈][低字节：夹爪状态]
0x07D1：[高字节：当前位置][低字节：故障位]
0x07D2：[高字节：力/电流反馈][低字节：当前速度反馈]
```

### 六个反馈字节怎样对应三个寄存器

主站使用 FC04 从 `0x07D0` 开始读取 3 个寄存器。响应中的字节数为 `0x06`，因为 3 个寄存器共有 6 个数据字节。

说明书中的一组完成响应数据为：

```text
00 F1 | FE 04 | 01 00
└07D0┘ └07D1┘ └07D2┘
```

对应关系为：

| 地址 | 寄存器值 | 高字节 | 低字节 | 含义 |
| --- | --- | --- | --- | --- |
| `0x07D0` | `0x00F1` | `0x00` | `0xF1` | 高字节暂不关注；低字节为状态位 |
| `0x07D1` | `0xFE04` | `0xFE` | `0x04` | 当前位置接近完全闭合；低字节为故障位 |
| `0x07D2` | `0x0100` | `0x01` | `0x00` | 力/电流反馈为 `0x01`；当前速度为 `0x00` |

完整响应报文还包含从站地址、功能码、数据字节数和 CRC：

```text
09 04 06 00 F1 FE 04 01 00 0B 3F
│  │  │  └──────数据6字节──────┘  └CRC┘
│  │  └─ 后续数据字节数
│  └─ FC04
└─ 从站地址
```

解析时应先根据字节顺序还原三个 16 位寄存器，再按各自定义拆分高低字节和状态位。

### 0x07D0 低字节状态位

| bit | 名称 | 含义 |
| ---: | --- | --- |
| 0 | `gACT` | 使能状态，与 `rACT` 对应 |
| 1 | Reserved | 保留 |
| 2 | `gMODE` | 当前工作模式 |
| 3 | `gGTO` | 当前动作状态 |
| 4-5 | `gSTA` | 复位、激活中或激活完成等状态 |
| 6-7 | `gOBJ` | 运动中、打开时接触物体、闭合时接触物体、到位但未检测到物体 |

`gSTA` 和 `gOBJ` 都占 2 bit，解析时需要右移和掩码：

```csharp
var gSta = (statusByte >> 4) & 0b11;
var gObj = (statusByte >> 6) & 0b11;
```

说明书定义的 `gOBJ`：

```text
0：手指正在向目标位置移动
1：打开过程中接触物体并停止，内夹模式检测到物体
2：闭合过程中接触物体并停止，外夹模式检测到物体
3：到达指定位置，但未检测到对象，或物体已丢失/脱落
```

某些工况下物体过细，夹爪可能已经夹住但没有可靠检测到力变化，说明书提示此时可能需要忽略 `gOBJ`。项目中不能只凭一个状态值判断所有夹取结果，必须结合具体物料和真机验证。

### 0x07D1 高低字节

```text
高字节：当前位置反馈，0x00 完全打开，0xFF 完全闭合
低字节：故障位
```

故障低字节按 bit 表示，包括未激活、控制命令错误、通信中断、过流、电压异常、使能故障、过温和产品自身故障等。

### 0x07D2 高低字节

```text
低字节：当前速度反馈 `gSP`
高字节：力状态/当前电机电流标幺值 `gCU`
```

`gCU` 反映电机电流相关状态，不应在没有设备标定和说明书换算依据时直接当作牛顿力值。

## MODE0 初始化流程

夹爪每次重新上电后需要重新使能。说明书给出的基本流程为：

```text
1. 写 rACT = 0，清除激活状态
2. 写 rACT = 1，请求使能
3. 周期读取 0x07D0
4. 等待 gACT = 1 且 gSTA = 3，确认激活完成
5. 检查故障寄存器后再执行动作
```

说明书示例：

```text
0x03E8 = 0x0000  清除激活
0x03E8 = 0x0001  请求激活
```

状态示例从未完成的 `0x11` 变化到激活完成的 `0x31`。这里指的是 `0x07D0` 的低字节。

使能时必须确保夹爪行程内没有明显障碍物，避免使能过程导致有效行程发生变化。

## MODE0 闭合动作流程

说明书的全速、全力、完全闭合示例一次写入三个连续寄存器：

```text
0x03E8 = 0x0009  rACT=1、rMODE=0、rGTO=1
0x03E9 = 0xFF00  目标位置=完全闭合
0x03EA = 0xFFFF  目标力=最大、目标速度=最大
```

流程：

```text
写入控制块
    ↓
收到 FC16 正常响应，只代表寄存器写入被接受
    ↓
周期读取 0x07D0～0x07D2
    ↓
检查状态、当前位置、故障和工件检测
    ↓
判断动作完成、夹到物体、未夹到物体或故障
```

## MODE0 打开动作流程

全速、全力、完全打开示例：

```text
0x03E8 = 0x0009  rACT=1、rMODE=0、rGTO=1
0x03E9 = 0x0000  目标位置=完全打开
0x03EA = 0xFFFF  目标力=最大、目标速度=最大
```

同样需要轮询反馈寄存器，不能把 FC16 写响应直接当作动作完成。

## 为什么一次写三个寄存器

动作需要同时给出：

```text
是否执行
目标位置
目标速度
目标力
```

这些字段分布在连续的 `0x03E8～0x03EA`。使用 FC16 一次写入控制块，可以让夹爪接收到一组完整参数，减少分别写入时出现“新命令配上旧参数”的中间状态。

是否保证严格原子应用仍取决于设备固件，但说明书动作示例采用 FC16，应优先遵循说明书。

## MODE1 暂不展开

MODE1 将位置、速度和力预先保存在最多 8 组预设参数中，动作时在 `0x03E8` 高字节写入指令编号。它适合参数固定、频繁复用的场景。

物料台项目是否使用 MODE1 尚需结合实际控制需求决定。若每次动作需要动态位置、速度和力，MODE0 更直接。

## 开发时需要验证的事项

1. 实际夹爪从站地址和串口参数。
2. 固件是否与 V1.1 说明书寄存器布局一致。
3. 使能、打开、闭合时 `gACT`、`gGTO`、`gSTA`、`gOBJ` 的真实变化。
4. 目标位置与实际夹持尺寸的换算和安全余量。
5. 不同物料下 `gOBJ` 是否能可靠检测到夹持。
6. 力和速度取值范围的安全上限。
7. 通信中断、过流、电压异常和急停后的恢复流程。
