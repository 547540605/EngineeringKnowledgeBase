## 关键陷阱：32 位寄存器默认“低字在前（CDAB）”

这是对接 SV126 驱动器时**最容易写错的底层规则**。

* **单个 16 位寄存器（WORD）**：采用标准 Modbus 大端序（高字节在前，低字节在后，`AB`）。
* **连续两个寄存器组成的 32 位数据（DWORD / `INT32` / `UINT32`）**：受通讯参数寄存器 `0x0009` 的 `Bit 14` 控制，**出厂默认 `Bit 14 = 0`，表示低 16 位字在前（低地址寄存器）、高 16 位字在后（高地址寄存器），单字内部仍为高字节在前（即 `CD AB` 字序）**！

### 正数 32 位示例：写入 `10000`（`0x00002710`）

以使用 `0x10` 功能码向细分寄存器 `0x0024~0x0025`（或绝对位置 `0x00D0~0x00D1`）写入十进制 `10000` 为例：

```text
32 位数值：10000 = 0x0000_2710
  ├─ 低 16 位字 (Low Word)  = 0x2710  ──► 放入起始地址 0x0024（报文中发 27 10）
  └─ 高 16 位字 (High Word) = 0x0000  ──► 放入后续地址 0x0025（报文中发 00 00）

手册真实请求报文：
01  10  00 24  00 02  04  27 10  00 00  FB 35
│   │   └起始┘ └数量┘ │   └低字┘ └高字┘ └CRC┘
│   └─ FC16           └─ 4 字节数据
└─ 站号 1
```

若误用 Python `struct.pack('>i', 10000)`（标准大端 `00 00 27 10`），驱动器会将其解析为 `0x2710_0000` = 十进制 `655,360,000`，导致参数越界或电机疯狂跑飞！

### 负数 32 位补码示例：写入 `-8000`（`0xFFFFE0C0`）

向实时绝对位置寄存器 `0x00E8~0x00E9` 写入 `-8000`：

```text
-8000 的 32 位有符号补码 = 0xFFFF_E0C0
  ├─ 低 16 位字 = 0xE0C0  ──► 先发 E0 C0
  └─ 高 16 位字 = 0xFFFF  ──► 后发 FF FF

手册真实请求报文：
01  10  00 E8  00 02  04  E0 C0  FF FF  CA 0D
```

### Python 正确的 32 位打包与解包写法

```python
import struct


def pack_int32_cdab(val: int) -> bytes:
    """将有符号 32 位整数打包为 SV126 默认的 [低字大端 + 高字大端] 4 字节"""
    u32 = val & 0xFFFFFFFF
    lo_word = u32 & 0xFFFF
    hi_word = (u32 >> 16) & 0xFFFF
    return struct.pack(">HH", lo_word, hi_word)


def pack_uint32_cdab(val: int) -> bytes:
    """将无符号 32 位整数打包为 [低字大端 + 高字大端] 4 字节"""
    lo_word = val & 0xFFFF
    hi_word = (val >> 16) & 0xFFFF
    return struct.pack(">HH", lo_word, hi_word)


def unpack_uint32_cdab(data4: bytes) -> int:
    """从 0x03 返回的 4 个数据字节还原无符号 32 位整数"""
    lo_word, hi_word = struct.unpack(">HH", data4)
    return (hi_word << 16) | lo_word


def unpack_int32_cdab(data4: bytes) -> int:
    """从 0x03 返回的 4 个数据字节还原有符号 32 位整数"""
    u32 = unpack_uint32_cdab(data4)
    return u32 - 0x100000000 if (u32 & 0x80000000) else u32
```

## 状态寄存器（`0x0006~0x0007`）与报警码（`0x00A3`）详解

### 1. 32 位运行及输入状态寄存器（`0x0006~0x0007`）

主站发送 `01 03 00 06 00 02 24 0A` 读取 2 个字时，返回的 4 个数据字节先按 `CDAB` 还原为 32 位无符号整数 `status_u32 = unpack_uint32_cdab(resp[3:7])`（其中 `Bit 0~15` 来自 `0x0006`，`Bit 16~31` 来自 `0x0007`）：

| Bit 位 | 名称 | 取值含义 |
| ---: | --- | --- |
| `0 ~ 7` | `X0 ~ X7` 输入状态 | `1`：对应端口有输入信号（光耦导通）；`0`：无输入 |
| `8 ~ 9` | 电机运行状态 | `00` (0)：电机空闲静止<br>`01` (1)：即将启动 / 预停止<br>`10` (2)：即将停止 / 预运行<br>`11` (3)：电机正在运行 |
| `10` | 位置超差警告 `X10` | 闭环下转子位置与命令位置差超过 `0x0010` 设定阈值时为 `1` |
| `12` | **到位输出标识 `X12`** | `1`：已到达目标位置；`0`：运行中 |
| `13` / `14` | 软负限位 / 软正限位 | 到达软件负/正限位时置 `1` |
| `15` | **原点完成标志 `X15`** | `1`：在原点 / 回零已完成；`0`：不在原点 |
| `16` | 使能电平标志 `X16` | 反映当前使能电平状态 |
| `21` | **驱动器报警状态 `X21`** | `1`：驱动器处于报警状态（可继续读 `0x00A3` 查具体原因）；`0`：正常 |

手册示例验证：当 `X1` 有输入（`Bit 1 = 1`）且电机正在运行（`Bit 9:8 = 11`）时，32 位状态值为 `0x0000_0302`。低字为 `0x0302`，高字为 `0x0000`，因此响应报文数据段正好是 `03 02 00 00`。

### 2. 报警代码寄存器（`0x00A3`）

当状态字 `Bit 21 == 1` 时，读取 `0x00A3`（16 bit）可获得上电以来的报警记录，每 4 个 bit 表示一个报警码：

```text
Bit 15~12：历史第三次报警
Bit 11~8 ：历史第二次报警
Bit  7~4 ：历史第一次报警
Bit  3~0 ：当前报警状态 (alarm_code = reg_00A3 & 0x0F)
```

报警码对照表（综合手册与厂商 `6.1.xml` 点位定义）：

| 代码 | 含义 | 常见现场原因 |
| ---: | --- | --- |
| `0` | 正常 | 无报警 |
| `1` | 电机相位过流 | 电机相间短路、电流设得过大、加减速过猛 |
| `2` | 供电电压过高 | 开关电源电压超限或急减速反向电动势泵升过高 |
| `3` | 供电电压过低 | 24V 电源未开、功率不足被拉低或供电线虚接 |
| `4` / `5` | 电机 A 相 / B 相开路 | 电机动力线未接牢或断线（可通过 `0x0012` Bit0 配置是否允许报警） |
| `6` | 位置超差或其他报警 | **闭环电机堵转、卡死、负载阻力过大**导致偏差超过 `0x000B/0x000C` 阈值 |
| `7` | 内部 24V 电压偏移 | 驱动器内部电源异常 |
| `8` / `9` | AI / BI 电压错误 | 采样电路异常 |
| `10` | 编码器错误 | 闭环编码器排线松动或磁编异常 |
| `11` / `12` | 数据存储错误 / 电机过载 | 新版固件扩展报警码 |

## 新老协议速度寄存器差异（`0x00D8` vs `0x009A`）

SV126.1 手册红字标注与厂商上位机 `CheckButtonMode7()` 逻辑共同明确了版本分界：

* **固件版本 `< SV113`（或 `0x0012` Bit 10 强制切为老协议）**：
  * 目标运行速度写 `0x009A`（`UINT16`，单位 `1 rpm`，写 `60` 代表 `60 rpm`）。
  * 实时速度读 `0x0019`（`INT16`，单位 `1 rpm`；注：固件 `118+` 后 `0x0019` 改作实际给定电流）。
* **固件版本 `>= SV113` 且保持默认新协议（`0x0012` Bit 10 = `0`）**：
  * **目标运行速度应读写 `0x00D8~0x00D9`**（`INT32`，单位 **`0.01 rpm`**！例如设定 `60 rpm` 需写入 `6000`，设定 `500 rpm` 需写入 `50000`，按 `CDAB` 打包）。
  * **实时速度应读取 `0x00D6~0x00D7`**（`INT32`，单位 **`0.01 rpm`**）。

此外需注意**启动速度（`0x0096`）与停止速度（`0x0097`）**出厂默认均为 `50 rpm`。在需要低冲击平顺起步的往复测试中，可根据现场表现将 `0x0096` / `0x0097` 下调（例如 `0 ~ 10 rpm`），配合 `0x0098` / `0x0099` 加减速时间获得完整梯形加减速过渡。

## 传感器回原点（Homing）寄存器拼装详解

通过 `X2` 光电传感器执行回零涉及三个寄存器：

### 第一步：配置原点输入端口（`0x009C`）

寄存器 `0x009C` 高字节配置外部使能口，低字节配置原点传感器口：

```text
Bit 15~13：使能口开关（000=取消，001=启用）
Bit 12   ：使能信号（0=PNP，1=NPN）
Bit 11~8 ：使能端口号（0~15 对应 X0~X15）
------------------------------------------------
Bit  7~5 ：原点口开关（000=取消，001=启用）
Bit  4   ：原点有效信号（0=低电平有效/PNP/无输入触发，1=高电平有效/NPN/有输入触发）
Bit  3~0 ：原点端口号（0~15 对应 X0~X15，X2 对应 2）
```

例如不使用外部使能口，将 **NPN 常开（遮挡时驱动器有输入）传感器接在 `X2`**：
* `Bit 7~5 = 001` (`1 << 5 = 0x20`)
* `Bit 4 = 1` (`1 << 4 = 0x10`)
* `Bit 3~0 = 0010` (`2 = 0x02`)
* 组合结果 = `0x0032`（报文：`01 06 00 9C 00 32 C8 31`）。

### 第二步：配置二次回原点退离距离（`0x009D`）

```text
Bit 15   ：第一次触发原点后退离的方向（0=CW 正向，1=CCW 反向）
Bit 14~0 ：离开原点脉冲数（0~32767，例如 500 脉冲 = 0x01F4）
```

若后面执行回原点选择“反向（`1`）找原点”，这里通常选“正向（`0`）退离 `500` 脉冲”，写入 `0x01F4`。

### 第三步：触发执行回原点控制字（`0x00C9`）

`0x00C9` 是无记忆动作触发寄存器，写入后电机立即开始寻零：

```text
Bit 15   ：粗寻回原点方向（0=正向 CW，1=反向 CCW）
Bit 14~6 ：粗寻回原点速度（0~511，单位：1 rpm）
Bit  5   ：碰到原点时的停止方式（0=减速停止，1=立即停止）
Bit  4~0 ：二次精寻速度档位（0~31，实际速度 = 设置值 × 5 rpm；设为 0 表示不做二次回原）
```

Python 位拼装公式：

```python
slow_factor = min(31, max(1, slow_speed_rpm // 5))
cmd_word = (
    ((direction & 0x01) << 15)
    | ((fast_speed_rpm & 0x01FF) << 6)
    | ((stop_mode & 0x01) << 5)
    | (slow_factor & 0x1F)
)
```

下发 `0x00C9` 后，短暂延时 `200~300 ms` 让电机离开静止态，随后轮询 `0x0006~0x0007` 状态字：
* 若 `Bit 21 == 1`：回零途中发生报警，立即中断报错；
* 当 `Bit 15 == 1`（`home_done`）且 `Bit 9:8 == 00`（`is_idle`）时：传感器捕获完成，驱动器内部已自动置零。此时若有夹具安装偏角 `home_offset_deg`，再走偏移脉冲并向 `0x00D2~0x00D3` 写入 `0` 完成几何对中。

## 绝对位置指令：`0x00D0` 与 `0x00E8` 的区别

| 寄存器 | 生效条件 | 适用场景 |
| --- | --- | --- |
| `0x00D0~0x00D1` (208) | **仅电机完全停止（空闲）时写入才生效**；若电机还在减速尾声未停稳就写入，指令会被忽略 | 严格分步定位（必须先轮询确认 `is_idle` 到位停稳，再发下一段） |
| `0x00E8~0x00E9` (232) | **电机静止或运行中写入均立即生效**，运行中收到新目标会强行接管当前运动并转向新目标 | 动态改目标位置、厂商上位机自带的 `Step` 往复运行模式，或运行中紧急指令回 `0` |

## 理解厂商上位机（`Leesn-Config` / `Step-Config`）的结构

厂商提供的调试上位机由**通用组态数据壳（左侧寄存器变量树）+ 内嵌网页控制面板（`/yzd/485.asp`）**组成，阅读时按以下映射理解即可：

1. **为什么刚打开右侧是一张属性表**：默认选中的是组态树节点属性视图，点击顶部菜单 **`ShowPage(显示页面)`** 才会切换到图形化标签页。
2. **左侧界面（7 个标签页）= 直接实时读写寄存器**：点击某个参数后的【设置】按钮，本质是立即发一条 `0x06` 或 `0x10` 报文修改 RAM 参数；点击右下角【断电保存】则是向 `0x00DC` 发 `1`。
3. **右侧界面（PC 程序集 / `.pc` 文件）= 驱动器内置 PLC 脚本编程区**：
   * SV126 驱动器内部地址 `300`（`0x012C`）之后是一块可存指令和位置表格的**内置编程区**，可通过寄存器 `0x00DB` 启动/停止脱机自运行，用 `0x0076~0x0077` 读取循环计数。
   * 若我们自己的上位机采用**PC 线程直接发定位指令 + 轮询状态计数**的方案，则**完全不需要使用右侧的内置编程区**，只需确保 `0x00DB` 未处于自运行状态、且 `0x009F` 处于 `3`（IO/总线控制模式）即可。

## 真机联调必查清单

1. 用 `0x03` 读 `0x0002~0x0003` 确认固件版本号（如 `>= 113`），并读 `0x0009` 确认 `Bit 14` 字序设置（默认 `0` 为 `CDAB`）。
2. 读 `0x009F` 确认控制模式为 `3`（非脉冲模式），读 `0x0012` 确认 `Bit 10` 为 `0`（新协议）。
3. 写入细分 `36000` 到 `0x0024~0x0025` 后，立刻回读 `0x0024~0x0025`，验证读回数值确为 `36000`（第一时间排除字序颠倒问题）。
4. 手动遮挡/移开 `X2` 光电开关，观察 `0x0006` 的 `Bit 2` 跳变方向，确认 `0x009C` 应写 `0x0032` 还是 `0x0022`。
5. 低速（如 `15~30 rpm`）、小角度（如 $\pm 10^\circ$）空载测试正反定位与回零偏移，确认正方向定义（`0x006B` CW/CCW）与夹具机械方向一致后再上试样。
