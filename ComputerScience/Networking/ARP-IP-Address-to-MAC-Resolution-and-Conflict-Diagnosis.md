# ARP：IP 到 MAC 映射异常与同网段通信故障排查

## 所属领域

`Computer Science > Networking > Ethernet / IPv4 / ARP`

相关知识：以太网帧、IPv4 路由、交换机 MAC 地址表、Wi-Fi AP、随机 MAC、IP 地址冲突、Proxy ARP。

## 问题现象

两台主机看起来都处于同一 IPv4 网段。一台可访问手机，另一台无法 Ping 或建立 TCP 连接；失败主机的路由表也显示目标网段为“在链路上”。

排查中，手机已确认的 MAC 为 `0a-69-b6-b8-24-fe`，但失败主机的 ARP 表将同一 IP `192.168.1.34` 解析为另一 MAC `24-b2-b9-48-5b-d5`：

```text
正常主机：192.168.1.34 -> 0a-69-b6-b8-24-fe
失败主机：192.168.1.34 -> 24-b2-b9-48-5b-d5
```

重新插拔失败主机的网线后，ARP 映射恢复为手机的正确 MAC，通信恢复。

## 原理

同一子网内发送 IPv4 包时，主机不经过默认网关，而是先通过 ARP 查询目标 IP 对应的 MAC。

```text
ARP 查询：谁拥有 192.168.1.34？
正确应答：192.168.1.34 的 MAC 是 0a-69-b6-b8-24-fe
```

随后发送的数据帧同时含有两层目的地址：

```text
以太网目的 MAC：0a-69-b6-b8-24-fe
IPv4 目的 IP：192.168.1.34
```

交换机按目的 MAC 转发帧。若 ARP 映射错误，帧会被交给错误 MAC 所在设备；该设备发现 IPv4 目的地址不是自己后通常丢弃，因此真实手机收不到 Ping 或 TCP 请求。即使 IP 地址、掩码、路由都正确，通信仍会失败。

## 结论与根因范围

同一 IP 在同一二层广播域内长期解析出两个不同 MAC，说明存在异常或状态切换。常见原因：

- 另一设备配置或短时占用了相同 IP，发生 ARP 抢答；
- 路由器、交换机或 AP 的 Proxy ARP / 无线客户端代理配置异常；
- 主机、交换机端口或 AP 保留了旧的 ARP/MAC 学习状态。
- 手机 Wi-Fi 从设备 MAC 切换为随机 MAC（或反向切换）后，部分主机或网络设备仍保留旧映射。

重新插拔网线会使网卡链路重新建立，并触发邻居/ARP 表和交换机 MAC 学习状态更新，因此可能恢复正确映射；这是一种恢复手段，不是根因证明。

## 手机 Wi-Fi 的设备 MAC 与随机 MAC

设备 MAC 是 Wi-Fi 网卡的硬件身份，通常固定；随机 MAC（也称私有 MAC）是操作系统为 Wi-Fi 连接生成的软件身份。其目的不是改变 IP，而是减少不同 Wi-Fi 网络通过固定 MAC 长期追踪同一设备的可能性。

手机通常可在某个 Wi-Fi 的详情页选择两种模式：

```text
设备 MAC：使用 Wi-Fi 网卡原始 MAC。
随机 MAC：使用该 Wi-Fi 的私有/随机 MAC。
```

随机 MAC 在同一 Wi-Fi 下通常可以保持稳定，但在切换“设备 MAC/随机 MAC”、忘记并重新加入网络、重置网络设置或设备策略调整后可能变化。MAC 改变时，手机仍可能继续使用原 IP；网络中残留的 `IP -> 旧 MAC` 映射会将同网段数据送错对象，直到 ARP 或网络设备的学习状态刷新。

对需要固定 IP、MAC 白名单、DHCP 保留地址或现场 ARP 排查的设备，应明确记录实际使用的 MAC，并固定选择一种模式。若以“设备 MAC”作为网络侧绑定依据，则手机端也应选择设备 MAC；若使用随机 MAC，则 DHCP 保留、白名单和排查记录必须使用该 Wi-Fi 当前显示的随机 MAC。

## 排查步骤

在失败主机复现时，先不要插拔网线，记录：

```bat
ipconfig
route print
arp -a 192.168.1.34
ping -n 1 192.168.1.34
```

确认目标 IP 应有的 MAC 后，清除该条邻居记录并重新 ARP：

```bat
arp -d 192.168.1.34
ping -n 1 192.168.1.34
arp -a 192.168.1.34
```

判断：

- 清除后立即恢复正确 MAC：优先检查失败主机旧 ARP 缓存或网络设备的暂态学习记录。
- 清除后仍得到错误 MAC：存在设备或网络设备持续为该 IP 应答；排查 IP 冲突、AP/交换机 Proxy ARP 和端口隔离策略。
- 两台主机同时对同一 IP 得到不同 MAC：对比它们所在有线端口、Wi-Fi SSID、AP 与 VLAN；必要时从交换机/AP 的 ARP 表和 MAC 地址表定位两个 MAC 的端口。

`tracert` 对同网段终端通常没有诊断价值：目标设备常不回应 TTL 超时报文。Ping 也不能替代业务连通性验证，最终还应测试实际 TCP/UDP 端口，例如：

```powershell
Test-NetConnection 192.168.1.34 -Port <端口号>
```
