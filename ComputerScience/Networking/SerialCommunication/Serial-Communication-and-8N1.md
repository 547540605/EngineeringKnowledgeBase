# 串口通信与 115200 8N1

## 所属领域

```text
Computer Science
└─ Networking
   └─ Serial Communication
      ├─ Baud Rate
      ├─ Data Bits
      ├─ Parity
      └─ Stop Bits
```

串口通信负责把一连串 bit 按照约定的时间和格式依次发送。它解决的是“双方怎样正确区分每一位以及每一帧数据”，不负责规定数据的业务含义。

## 什么是串行通信

串行通信把数据位沿一条通信通道按时间先后逐位发送：

```text
时间方向 →
0 1 0 1 1 0 1 0
```

“串行”强调的是一个 bit 接一个 bit 地传输。与之相对，并行通信可以同时传输多个 bit，但需要更多数据线。

一个程序要发送字节 `0x53`：

```text
0x53 = 二进制 0101 0011
```

在串行线路上，这些 bit 会按照协议规定的顺序和节奏逐个出现，而不是一次把整个字节放在线上。

## 串口双方为什么必须使用相同参数

发送方只是在电线上按照时间改变信号，接收方必须知道：

1. 每一个 bit 持续多长时间。
2. 从哪里开始算一帧数据。
3. 一帧中包含几个数据位。
4. 是否包含校验位。
5. 一帧在哪里结束。

这些规则由波特率、数据位、校验位和停止位共同确定。双方配置不一致时，接收方可能在错误时间采样，最终得到乱码、校验错误或完全收不到数据。

## 115200 8N1 的含义

夹爪说明书中的默认串口参数可以写成：

```text
115200, 8N1
```

其含义为：

| 参数 | 含义 |
| --- | --- |
| `115200` | 波特率为 115200 |
| `8` | 每帧包含 8 个数据位 |
| `N` | 无奇偶校验（None） |
| `1` | 1 个停止位 |

通常还隐含一个起始位，因此发送一个 8 位数据字节时，线路上至少包含：

```text
1 个起始位 + 8 个数据位 + 0 个校验位 + 1 个停止位
= 10 bit
```

## 波特率

波特率描述线路每秒进行多少次符号传输。在这里每个符号承载一个 bit，可以近似理解为每秒传输 115200 个线路 bit：

```text
115200 baud ≈ 每秒 115200 bit
```

但实际业务字节还包含起始位、校验位和停止位等开销。对于 8N1，一个数据字节在线路上占 10 bit，因此理论最大有效数据量约为：

```text
115200 ÷ 10 = 11520 byte/s
```

这只是未考虑帧间间隔、系统调度和协议开销的理论值。

波特率不是“设备越高越好”的自由设置。通信双方必须配置相同且设备必须支持。

## 数据位

数据位表示一帧中真正承载数据的位数。`8N1` 中的 `8` 表示每帧携带 8 个数据位，也就是一个 byte。

```text
8 data bits = 1 byte
```

## 奇偶校验位

校验位是在数据位后面额外增加的一个 bit，用于检测单帧中的部分传输错误：

```text
N = None，无校验
E = Even，偶校验
O = Odd，奇校验
```

E、O、N 是通信双方预先约定的校验规则，不是三个固定的校验位数值。选择 E 或 O 后，串口硬件会根据每一帧数据中 1 的数量，动态计算该帧的校验位是 0 还是 1：

| 数据 | 数据中 1 的数量 | E 偶校验位 | O 奇校验位 |
| --- | ---: | ---: | ---: |
| `0x53 = 0101 0011` | 4（偶数） | 0 | 1 |
| `0x57 = 0101 0111` | 5（奇数） | 1 | 0 |

因此，E 不代表校验位永远是 0，O 也不代表校验位永远是 1。它们规定的是添加校验位以后，1 的总数必须为偶数还是奇数。

### 无校验 N

不添加校验位，也不在串口帧层检查数据位中 1 的数量。`8N1` 因此只有起始位、8 个数据位和停止位。

### 偶校验 E

发送方设置校验位，使“8 个数据位加校验位”中 1 的总数为偶数。

例如 `0x53` 的二进制是 `0101 0011`，其中有 4 个 1。4 已经是偶数，因此偶校验位为 0：

```text
数据中的 1：4 个
校验位：    0
总数：      4 个，仍为偶数
```

### 奇校验 O

发送方设置校验位，使“8 个数据位加校验位”中 1 的总数为奇数。同样使用 `0x53`：

```text
数据中的 1：4 个
校验位：    1
总数：      5 个，变为奇数
```

接收方按照相同规则重新统计。如果要求偶数却数出了奇数，就知道传输过程中可能发生错误，并报告奇偶校验错误。

奇偶校验只能检测错误，不能判断哪一位错了，也不能修复数据。它通常可以发现奇数个位发生翻转的错误，但偶数个位同时翻转时可能仍然通过校验。

`8N1` 中的 `N` 表示不添加奇偶校验位。Modbus RTU 仍会使用 CRC 检查整条报文，但 CRC 和串口奇偶校验属于不同层次：

```text
奇偶校验：检查一个串口数据帧
CRC：      检查一整条 Modbus RTU 报文
```

## 停止位

停止位标记一帧数据结束，并让线路保持空闲电平一段约定时间。`8N1` 最后的 `1` 表示保持 1 个 bit 的时间。

常见选择包括：

```text
1 个停止位
1.5 个停止位（少见，并非所有组合和设备都支持）
2 个停止位
```

例如：

```text
8N1：1 起始位 + 8 数据位 + 0 校验位 + 1 停止位 = 10 bit
8E1：1 起始位 + 8 数据位 + 1 校验位 + 1 停止位 = 11 bit
8N2：1 起始位 + 8 数据位 + 0 校验位 + 2 停止位 = 11 bit
```

两个停止位会给接收设备更多恢复和重新同步时间，对某些较慢或旧式设备更宽容，但每帧耗时更长，有效传输速度也会降低。

发送方和接收方必须使用兼容的停止位配置。接收方如果在应该出现停止位的位置没有检测到空闲电平，通常会报告帧错误（Framing Error）。

停止位不是程序发送的业务数据，它属于串口硬件在传输一帧时添加的格式信息。

## 起始位

常见异步串口在没有数据时保持空闲状态。发送方先发送一个起始位，通知接收方：新的一帧开始了，请按照约定波特率开始采样。

一帧 `8N1` 可以抽象为：

```text
空闲 | 起始位 | D0 D1 D2 D3 D4 D5 D6 D7 | 停止位 | 空闲
```

数据位在线路上的具体先后顺序通常是最低有效位先发送。这个“一个字节内部 bit 的发送顺序”与多个字节之间的大端、小端问题不是同一个概念。

## 串口参数不解释业务内容

配置 `115200 8N1` 后，通信双方只是具备了正确收发字节的条件。

例如收到：

```text
09 03 03 E8 00 01 ...
```

串口层只负责把这些字节正确送达。至于：

```text
09 是不是设备地址
03 是不是功能码
03 E8 是不是寄存器地址
```

要由上层 Modbus RTU 协议解释。

## 与 RS485 和 Modbus RTU 的关系

```text
串口参数：规定 bit 的节奏和帧格式
RS485：规定电气信号如何在线路上传输
Modbus RTU：规定字节如何组成请求和响应
设备寄存器表：规定数据对应什么设备功能
```

这几层互相配合，但不是同一个概念。

## 当前阶段应掌握

1. 串行通信是把 bit 按时间顺序逐个传输。
2. 双方串口参数必须一致。
3. `115200 8N1` 表示 115200 波特率、8 个数据位、无校验、1 个停止位。
4. 8N1 发送一个数据字节通常在线路上占用 10 bit。
5. 串口只负责可靠地收发字节，不解释 Modbus 业务含义。
