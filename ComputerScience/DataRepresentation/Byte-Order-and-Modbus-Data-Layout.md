# 字节序与 Modbus 数据排列

## 所属领域

```text
Computer Science
└─ Data Representation
   └─ Byte Order (Endianness)
```

字节序解决的问题是：一个数由多个字节组成时，这些字节按照什么顺序存储或传输。

## 为什么会有字节序

一个字节内部的 8 个 bit 已经有明确位置；只有一个字节时，不存在字节先后问题。

例如 `0x12` 只有一个字节，直接发送 `12` 即可。

而 `0x1234` 是一个 16 位数，包含两个字节：

```text
高字节：0x12
低字节：0x34
```

传输时既可以排列为 `12 34`，也可以排列为 `34 12`。通信双方必须约定一致，否则会解析成不同数值。

## 数值本身没有字节序

```csharp
ushort value = 0x1234;
```

这里的 `0x1234` 是一个整数常量，表示十进制数值 4660。十六进制写法按照从高位到低位的习惯书写，但这只是人类和编程语言表示数值的方式，并不代表它已经按照大端序存储或传输。

只有当这个数值被展开成多个实际字节时，才需要讨论字节序：

```text
数值：       0x1234        不谈字节序
大端字节流： 12 34         高字节在前
小端字节流： 34 12         低字节在前
```

因此，字节序描述的是“数值与多个字节之间如何映射”，而不是十六进制数字从左到右怎么写。

## 大端序与小端序

### 大端序

高字节在前，低字节在后：

```text
数值：0x1234
顺序：12 34
```

### 小端序

低字节在前，高字节在后：

```text
数值：0x1234
顺序：34 12
```

“大端”和“小端”描述的是多字节数值中字节的排列顺序，不是数值本身发生了变化。

## 顺序错误会发生什么

若发送方想表达 `0x1234`，但接收方把 `12 34` 当成小端序解析，就会得到 `0x3412`。

```text
0x1234 = 十进制 4660
0x3412 = 十进制 13330
```

报文可能长度正确、CRC 也正确，但业务数值完全错误，因此字节序问题通常不容易一眼发现。

## Modbus RTU 中的基本规则

Modbus 协议数据单元中的多字节字段通常采用高字节在前的排列方式。例如寄存器地址 `0x03E8` 在请求报文中排列为：

```text
03 E8
```

寄存器数据 `0x1234` 通常排列为：

```text
12 34
```

但是 Modbus RTU 报文末尾的 CRC 是一个特别规则：CRC 低字节先发送，高字节后发送。

```text
普通 16 位字段：高字节 → 低字节
CRC 字段：       低字节 → 高字节
```

因此不能简单认为“一整条 Modbus 报文全部采用同一种字节顺序”，应按字段规则组装和解析。

## 多个寄存器组成一个数值

一个 Modbus 寄存器是 16 bit。32 位整数或浮点数需要占用两个寄存器：

```text
32 bit 数据 = 寄存器 A + 寄存器 B
```

Modbus 规定了单个寄存器中字节的基本排列，但不同设备对两个寄存器谁在前可能有不同约定。例如 `0x12345678` 可能出现：

```text
12 34 56 78
56 78 12 34
34 12 78 56
78 56 34 12
```

因此解析 32 位或更长数据时，必须查看具体设备说明书，不能只凭“Modbus 默认大端”推断整个数据布局。

## C# 中手工按大端序组装

将 `ushort` 拆成高字节在前的报文：

```csharp
ushort value = 0x1234;

byte[] bytes =
[
    (byte)(value >> 8),
    (byte)(value & 0xFF)
];
```

上面的写法同时完成了“拆分字节”和“创建数组”。完全拆开后等价于：

```csharp
ushort value = 0x1234;

byte highByte = (byte)(value >> 8);   // 得到 0x12
byte lowByte = (byte)(value & 0xFF);  // 得到 0x34

byte[] bytes = new byte[2];
bytes[0] = highByte;
bytes[1] = lowByte;
```

也可以使用传统的数组初始化语法：

```csharp
byte[] bytes = new byte[]
{
    highByte,
    lowByte
};
```

`[ ... ]` 是现代 C# 的集合表达式。目标类型已经由左侧的 `byte[]` 指定，因此编译器知道要创建一个字节数组。方括号中的元素按照书写顺序依次成为 `bytes[0]`、`bytes[1]`。

这里先写高字节、再写低字节，所以数组中的实际顺序是：

```text
索引：   0     1
内容： 0x12  0x34
```

结果为：

```text
12 34
```

从两个大端序字节还原：

```csharp
ushort value = (ushort)((bytes[0] << 8) | bytes[1]);
```

## 与计算机内存字节序的区别

CPU 在内存中如何保存整数，与通信协议要求如何发送字节，是两个层面。

当前 Windows 与常见 x86/x64 计算机通常使用小端内存布局，但 Modbus 报文的寄存器地址和寄存器值仍按照协议要求组织。程序不能直接假设内存中的原始字节顺序正好等于协议顺序。

## 排查字节序问题

1. 先确认字段占几个字节或几个寄存器。
2. 查看设备说明书给出的示例报文。
3. 对照一个已知数值，例如用 `0x1234` 检查收到的是 `12 34` 还是 `34 12`。
4. 单独确认 CRC 的字节顺序。
5. 对 32 位数据额外确认寄存器顺序。
